# Roles - Spring AI and Ollama API

This example demonstrates how to prompt a locally hosted large language model
(LLM) using [Ollama](https://ollama.com/) with both **system** and **user**
messages.

**Ollama** is an open-source platform that allows developers to run LLMs
entirely on their own machines—eliminating the need for cloud APIs, access keys,
or concerns about data privacy. It supports multimodal inputs, tool calling, and
integrations with REST and
[Java](https://docs.spring.io/spring-ai/reference/api/chat/ollama-chat.html),
making it well suited for prototyping, debugging, and deploying LLM-powered
applications in a fully offline, customisable environment.

This example uses **Spring AI**, a Java-based framework for building LLM
applications. It provides tools for prompt management, chaining LLM calls,
memory handling, retrieval-augmented generation (RAG), and integration with
external data sources.

An alternative to Spring AI is
[LangChain4J](https://github.com/langchain4j/langchain4j), which also abstracts
interactions between LLMs and applications. However, this example specifically
demonstrates **Ollama with Spring AI**.

**What Are System and User Messages?**

- **User messages** contain direct questions or instructions from the user.
- **System messages** define the model’s behaviour, tone, or role, ensuring
  consistent responses throughout the conversation.

By combining these, you can tightly control how the LLM responds, which is
crucial when designing reliable applications.

**Mitigating Prompt Injection with System Messages and Templates**

System messages can also help mitigate **prompt injection attacks**, where
malicious user input attempts to override the model’s intended behaviour (for
example, by instructing it to ignore previous rules). By placing critical
behavioural instructions in the system message—rather than in user-provided
text—you create a stronger, higher-priority layer of control.

When combined with **prompt templates**, this becomes even more robust.
Templates allow developers to strictly structure how user input is inserted into
prompts, reducing the risk of users injecting conflicting instructions. For
example, a template might ensure that the user’s question is always wrapped in a
controlled format (e.g., _“The student asks: \[user input]”_), preventing them
from breaking out of the intended conversational context.

Together, **system messages** and **templated user input** form an effective
strategy for maintaining consistent behaviour and resisting attempts to
manipulate the model.

**System Message Example**

In this example, the system message instructs the LLM to behave as an
encouraging primary school teacher:

```
system> You are a friendly and knowledgeable primary school teacher. Speak clearly and kindly, using language suitable for children aged 11 to 15. Use simple examples, encourage curiosity, and explain difficult words in a fun, easy-to-understand way. Always be supportive and help students feel confident about learning.
```

Regardless of the user’s input, the LLM will maintain this persona, producing
responses that are consistent, age-appropriate, and aligned with the specified
teaching style.

This technique is essential for defining personas, controlling tone, and
ensuring predictable outputs in LLM-powered systems.

## Run the example

1. Download and setup Ollama

   If you haven’t already, please download and install Ollama from the
   [official download page](https://ollama.com/download), following the
   instructions provided. Ollama includes a command-line tool for managing and
   interacting with it.

   Models must be downloaded from a repository, such as the
   [Ollama Library](https://ollama.com/library) or
   [Hugging Face](https://huggingface.co/models). Ensure the model is saved in
   a supported format, such as
   [GPT-Generated Unified Format (GGUF)](https://huggingface.co/docs/hub/en/gguf).

   To list models installed locally, run:

   ```shell
   ollama list
   ```

   After a fresh installation, no models will be listed.

   ```

   ```

   To get started, download [LLaMA 2](https://ollama.com/library/llama2) with:

   ```shell
   ollama pull llama2
   ```
